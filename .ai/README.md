# AI assistant configuration

OneTerminal supports several AI coding assistants (Claude Code, GitHub Copilot, Devin,
Codex, Cursor, …) from **one tool-neutral source**. Each tool gets a thin generated
adapter in the location it expects. Rules that must hold are enforced by lefthook and CI,
not by any one assistant.

## Sources (edit these)

| Source                              | Purpose                                                                                        |
| ----------------------------------- | ---------------------------------------------------------------------------------------------- |
| `AGENTS.md` (root)                  | Repo-wide context: identity, layout, commands, generated files                                 |
| `<dir>/AGENTS.md` (nested)          | Context for one area, next to its code                                                         |
| `docs/conventions/*.md`             | Long-form rules (Rust, React, cross-platform, security, FDC3, scaffolder) — linked, not copied |
| `.ai/agents/*.md` _(planned)_       | Role definitions for reviewer / specialist agents                                              |
| `.ai/skills/*/SKILL.md` _(planned)_ | Repeatable workflows in the Agent Skills format                                                |

## Generated adapters (never edit)

| Generated file                               | From               | Read by                              |
| -------------------------------------------- | ------------------ | ------------------------------------ |
| `<dir>/CLAUDE.md`                            | `<dir>/AGENTS.md`  | Claude Code (`@AGENTS.md` import)    |
| `.github/copilot-instructions.md`            | root `AGENTS.md`   | GitHub Copilot (repo-wide)           |
| `.github/instructions/<dir>.instructions.md` | nested `AGENTS.md` | GitHub Copilot (`applyTo: <dir>/**`) |

Devin, Codex and Cursor read `AGENTS.md` files directly. For Devin, mirror the most
important rules into its Knowledge entries and link them back to the source file.

Generated files start with a `Generated by scripts/sync-ai-config.ts` marker. They are
copies, not symlinks, because Git for Windows checks symlinks out as plain files by default.

## Workflow

```sh
# edit AGENTS.md (root or nested) or add a new <dir>/AGENTS.md
npm run sync:ai          # regenerate adapters (formats them with Prettier)
npm run check:ai-drift   # what CI runs — exit 1 if adapters are stale
```

Commit the source and the regenerated adapters together.

## Writing guidance

- Write for any assistant: no tool-specific syntax (tool names, slash commands) in
  `AGENTS.md` or `docs/conventions/`.
- State facts an assistant can't derive from the code: invariants, why a constraint
  exists, OS quirks, what's generated, what's planned vs. implemented.
- Keep nested files short and specific; link to `docs/conventions/` for detail.
- Relative links are rewritten automatically when content is copied into `.github/`.
- AI context files are never shipped to scaffolded workspaces — the template extractor
  skips `AGENTS.md` and `CLAUDE.md`.
