# AI assistant configuration

OneTerminal supports several AI coding assistants (Claude Code, GitHub Copilot, Devin,
Codex, Cursor, …) from **one tool-neutral source**. Each tool gets a thin generated
adapter in the location it expects. Rules that must hold are enforced by lefthook and CI,
not by any one assistant.

## Sources (edit these)

| Source                              | Purpose                                                                                        |
| ----------------------------------- | ---------------------------------------------------------------------------------------------- |
| `AGENTS.md` (root)                  | Repo-wide context: identity, layout, commands, generated files                                 |
| `<dir>/AGENTS.md` (nested)          | Context for one area, next to its code                                                         |
| `docs/conventions/*.md`             | Long-form rules (Rust, React, cross-platform, security, FDC3, scaffolder) — linked, not copied |
| `.ai/agents/*.md`                   | Role definitions for reviewer / specialist agents (format below)                               |
| `.ai/skills/*/SKILL.md` _(planned)_ | Repeatable workflows in the Agent Skills format                                                |

## Generated adapters (never edit)

| Generated file                               | From                   | Read by                              |
| -------------------------------------------- | ---------------------- | ------------------------------------ |
| `<dir>/CLAUDE.md`                            | `<dir>/AGENTS.md`      | Claude Code (`@AGENTS.md` import)    |
| `.github/copilot-instructions.md`            | root `AGENTS.md`       | GitHub Copilot (repo-wide)           |
| `.github/instructions/<dir>.instructions.md` | nested `AGENTS.md`     | GitHub Copilot (`applyTo: <dir>/**`) |
| `.claude/agents/<name>.md`                   | `.ai/agents/<name>.md` | Claude Code subagent                 |
| `.github/agents/<name>.agent.md`             | `.ai/agents/<name>.md` | GitHub Copilot custom agent          |

Devin, Codex and Cursor read `AGENTS.md` files directly; the root `AGENTS.md` lists the
review agents so they can follow `.ai/agents/<name>.md` as a role. For Devin, mirror the
most important rules into its Knowledge entries and link them back to the source file.

Generated files start with a `Generated by scripts/sync-ai-config.ts` marker. They are
copies, not symlinks, because Git for Windows checks symlinks out as plain files by default.

## Workflow

```sh
# edit AGENTS.md (root or nested), add a new <dir>/AGENTS.md, or edit .ai/agents/*.md
npm run sync:ai          # regenerate adapters (formats them with Prettier)
npm run check:ai-drift   # what CI runs — exit 1 if adapters are stale
```

Commit the source and the regenerated adapters together.

## Agents

| Agent                                                        | Role                                                      |
| ------------------------------------------------------------ | --------------------------------------------------------- |
| [cross-platform-reviewer](agents/cross-platform-reviewer.md) | Windows (WebView2) + macOS (WKWebView) correctness review |
| [fdc3-conformance](agents/fdc3-conformance.md)               | FDC3 3.0 / DACP conformance review of broker, bus, plugin |

### Source format

```markdown
---
name: my-agent # must match the file name
description: One or two sentences — what it does and when to use it. Tools use this to pick the agent.
mode: read-run # read-only | read-run | write
claude-model: sonnet # optional: sonnet | opus | haiku | inherit
---

Role prompt in plain Markdown, written for any assistant: what to read first, scope,
procedure, and the exact report format.
```

Frontmatter is flat `key: value` lines (no nesting or lists). `mode` maps to each tool's
tool list:

| `mode`      | Claude Code `tools`                   | Copilot `tools`                         |
| ----------- | ------------------------------------- | --------------------------------------- |
| `read-only` | `Read, Grep, Glob`                    | `["read", "search"]`                    |
| `read-run`  | `Read, Grep, Glob, Bash`              | `["read", "search", "execute"]`         |
| `write`     | `Read, Grep, Glob, Bash, Edit, Write` | `["read", "search", "edit", "execute"]` |

Reviewers are `read-run`: they need a shell for `git diff` and tests, and their prompt
forbids edits. Check the Copilot custom-agent docs when adding a mode — its tool aliases
may change.

### Using an agent

- **Claude Code:** ask for it by name ("run the fdc3-conformance agent on this branch"),
  or let Claude pick it from the description. New agent files load at session start.
- **GitHub Copilot:** pick the agent in the agent picker (VS Code chat, or the coding
  agent on github.com).
- **Devin, Codex, Cursor, others:** "Follow `.ai/agents/<name>.md` and review this branch."

## Writing guidance

- Write for any assistant: no tool-specific syntax (tool names, slash commands) in
  `AGENTS.md` or `docs/conventions/`.
- State facts an assistant can't derive from the code: invariants, why a constraint
  exists, OS quirks, what's generated, what's planned vs. implemented.
- Keep nested files short and specific; link to `docs/conventions/` for detail.
- Relative links are rewritten automatically when content is copied into `.github/`.
- AI context files are never shipped to scaffolded workspaces — the template extractor
  skips `AGENTS.md` and `CLAUDE.md`.
